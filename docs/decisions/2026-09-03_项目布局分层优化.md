# 决策记录：项目布局分层优化

> 日期：2026-09-03  
> 状态：已执行

## 背景

原目录的顶层边界基本合理，但 `scripts/` 同时放置仿真、后处理、文献下载和统计脚本；`docs/reports/` 同时混放设计分析、COMSOL 结果、加工汇报和文献统计。`docs/references/` 又与根部 `references/` 含义重叠，增加了接手和路径维护成本。

## 决策

1. 保留稳定的核心边界：`src/`、`configs/`、`experiments/`、`literature/`、`references/`、`fabrication/` 和 `artifacts/`。
2. `scripts/` 按职责拆为 `simulation/`、`postprocess/`、`literature/`；可复用逻辑继续只放 `src/gwm_workflow/`。
3. `docs/reports/` 按内容拆为 `design/`、`simulation/`、`fabrication/`、`literature/`。
4. 项目指南、模板和旧约定分别归入 `docs/guides/`、`docs/templates/`、`docs/archive/`；新增 `docs/README.md` 作为文档入口。
5. 不移动论文 PDF、实验数据或已接受结果；历史 `resolved_config.json` 作为证据链保留当时命令字符串，不追写新路径。活动配置与文档统一使用新路径。

## 验收标准

- 根目录 README、项目配置、轨道 README 和活动配置不再引用旧入口。
- 所有 Python 脚本可编译，纯 Python 测试通过，mock 工作流可运行。
- Markdown 相对链接、JSON、PDF manifest 与关键资产路径通过自动检查。
